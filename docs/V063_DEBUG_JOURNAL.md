## 수정 및 검증 진행

숫자/길이 보호 실패를 행별 별도 ai_correction_issue로 저장한다. 같은 원문·모델·용어집 조합은 자동 반복하지 않고 명시적 재시도로 다시 처리한다. 분할 발언은 일부만 적용하지 않는다. 응답 형식/ID 오류는 계속 전역 실패로 처리한다.

실시간 요약은 수동 검토본 → 유효한 AI 보정본 → 최초 원문 순서로 사용하며 같은 입력을 서명·체크포인트·응답 경쟁 검사에 사용한다. 구조화 회의록의 원문 근거 검증은 유지한다. 요약 표시 문자열만 완결된 확인 문장으로 표시하며 저장 요약을 덮어쓰지 않는다.

첫 수정 후 React 대역 38건, 핵심 회귀 52건, 요약 표시 11건, TypeScript 검사 통과. 추가로 분할 발언 원자성, 저장된 확인 구간과 변경된 원문 재처리, 늦은 이전 요약 차단, 실제 보정 훅 이후 요약 갱신을 검증해 React 대역 42건 모두 통과했다.

초기 경쟁 테스트는 공유 generateText의 직렬 요청 특성을 무시해 대기 중 보정 완료를 기대했다. 원문 요약 완료 후 실제 보정 훅 갱신 시험과, 저장된 보정이 바뀐 경우 이전 요약 응답 차단 시험으로 각각 검증한다. 프로덕션 동작을 테스트 타이밍에 맞춰 바꾸지 않았다.
