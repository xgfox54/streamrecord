# 분야별 단어장 3,000자 확장

이전 구현은 11개 분야 전체에 500개 단어가 있었고 기록 입력 및 AI 보정 요청에 500자 제한이 있었다. 사용자에게 허용받은 대안인 단어장별 약 3,000자를 적용했다. 500개 단어를 분야마다 정확히 맞춘 구성은 아니며, 구분자를 포함한 글자 수를 기준으로 한다.

| 분야 | 단어 수 | 글자 수 |
|---|---:|---:|
| 의회 회의·호칭 | 506 | 2,997 |
| 행정사무감사·질문 | 497 | 3,000 |
| 예산·결산 | 477 | 3,000 |
| 조례·자치·행정체제 | 489 | 2,999 |
| 제주 지명·기관·인물 | 486 | 2,998 |
| 복지·보건·안전 | 466 | 3,000 |
| 환경·농업·해양 | 491 | 3,000 |
| 관광·문화·체육 | 474 | 2,999 |
| 도시·교통·건설 | 479 | 2,999 |
| 경제·산업·일자리 | 478 | 3,000 |
| 교육·청소년 | 455 | 2,999 |

분야별 용어를 먼저 배치하고 회의·행정 공통 용어를 뒤에 넣었다. 분야 안에서는 중복이 없으며 여러 분야에서 공유하는 공통 용어는 합칠 때 한 번만 넣는다. 기존 실제 회의 오인식 용어를 보존하고 새로 확장한 용어는 편집 구성 자료로 표시한다. 공식 용어집 또는 검수 완료를 주장하지 않는다.

## 적용 범위

- 직접 입력과 선택·자동 선택한 세트를 합친 한 기록의 AI 보정 참고 용어는 최대 3,000자다. 여러 분야는 주요 용어부터 번갈아 넣고 제외된 용어를 화면에 표시한다.
- 마이크·PC 소리·YouTube 및 공통 녹음 옵션의 입력 제한과 글자 수 안내를 동일한 상수로 관리한다.
- AI 보정 요청에서 기존 500자 절단을 제거했다. 기존 저장 입력은 삭제하지 않으며 한도 초과 입력을 AI에 보낼 때는 용어 중간을 잘라 보내지 않는다.
- 원문 음성 인식·저장 음성 재처리·요약·회의록 요청에는 단어장을 직접 전달하지 않는다.
- 자동 분야 판별은 기존 분야별 대표 용어로 유지한다. 공통 행정 용어만 말해도 여러 분야가 잘못 선택되는 것을 방지한다.
- 보정은 기존 4구간/발언 합계 1,800자 묶음을 유지하며 단어장 확장으로 추가 보정 요청을 만들지 않는다.

## 검증

PASS: 단어장 20개 검사, 실제 React 세션 78개 검사, 코어 66개 검사, TypeScript 검사, 프로덕션 빌드. 3,000자 단어장의 마지막 용어까지 AI 요청에 전달하고 8구간을 기존처럼 2회 요청으로 처리함을 네이티브 대역으로 확인했다. 수동 입력 보존, 중복 제거, 자동 선택, 재시작 보정 재사용, 원문 인식에 단어장을 전달하지 않는 회귀 검사도 통과했다.

PASS: 프로덕션 Chrome에서 6개 시나리오. 한 분야 전체 적용, 여러 분야와 수동 용어 합산 및 생략 안내, 입력창 3,000자 한도, 375/768/1280px 가로 넘침 없음 및 WCAG 자동 검사 위반 없음. 화면을 직접 확인했다. 브라우저 네이티브 경계는 검증 대역이며 실제 설치본 실행 버전 증거가 아니다.

검증 명령 (소스 app/frontend에서 실행):

```text
node tests/glossary-packs.cjs
node tests/stream-record-ui.cjs
npm run test:stream-record
npm run typecheck
npm run build
node tests/glossary-browser.cjs
```

## 속도와 배포 경계

로컬 Whisper 입력이나 보정 요청 수는 늘리지 않았다. 3,000자 실제 단어장과 긴 발언을 함께 직렬화한 요청은 예시에서 4,514자/10,622바이트 및 3,532자/8,232바이트로 네이티브 6,000자 입력 한도 이내였다. 실제 GPT 응답 시간·새 단어장 적용 후 정확도는 측정하지 않았다. 이 오프라인 검사만으로 클라우드 처리 지연이 없다고 판단하지 않으며, 현재는 3,000자를 유지한다.

v0.7.3에 포함한다. 설치·GitLab 배포의 실제 검증 결과와 실기기 경계는 해당 릴리스의 첨부 보고서를 참고한다.
