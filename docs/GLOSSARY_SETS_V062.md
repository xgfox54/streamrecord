# 주제별 전문 용어 세트 · v0.6.2

2026-10-01에 확인한 공식 제주특별자치도의회 제454회 제7차 본회의(2026-09-22)의 의사일정·상정 안건을 검토해 주제별로 직접 분류한 초안이다. 전체 회의록을 자동으로 군집화하거나 빈도 분석한 결과가 아니다. 회의 주제를 자동 추정하지 않으며, 전문 용어 검수와 음성 인식 효과 검증도 완료되지 않았다.

## 근거와 범위

공식 원문: [제454회 제7차 본회의](https://record.council.jeju.kr/CLRecords/Retrieval2/index.php?daesu=13&hfile=13A0110454071.html).
기존 `assets/glossary/jeju-council-candidates.json`도 같은 회의를 근거로 하며, 수집 시각·SHA-256·출현 위치·빈도가 있다. 그 후보들은 개별 선택으로 유지했다. 새 세트는 안건의 명사구와 해당 위원회 명칭을 골라 구성했다. 긴 조례안 제목에서 주제어를 분리했으며, 문장·개인 이름·발언 원문은 세트에 복제하지 않았다. 한 회의의 의제에 제한되므로 농수축산·관광·재난 등 모든 분야를 포괄한다고 볼 수 없다.

## 사용 동작

- 기본은 모두 비선택이다. 주제를 여러 개 체크해도 입력은 바뀌지 않는다.
- 세트별 전체 용어를 펼쳐 볼 수 있고, 현재 선택한 용어·중복 제외 수·추가 후 글자 수·한도로 생략될 용어를 적용 전에 확인한다.
- 추가 버튼은 수동 입력 뒤에 용어를 붙인다. 쉼표·세미콜론·줄바꿈으로 나눈 기존 용어와 정확히 같은 후보는 재추가하지 않는다. 비교 시 앞뒤 공백을 제거하며, 기존 문자열 자체는 공백까지 보존한다. 띄어쓰기 변형·동의어를 임의 병합하지 않는다.
- JavaScript 문자열 길이 기준 500자 한도는 기존 입력 필드와 같다. 긴 후보를 생략해도 뒤의 짧은 후보가 들어갈 수 있다. 기존 입력이 이미 한도를 넘으면 삭제·절단하지 않고 새 후보를 생략한다.
- 생략된 후보는 상태 메시지로 명시하고 개별 선택에 남겨 재시도할 수 있다. 성공한 세트 선택은 해제한다. 선택 해제는 실제 입력을 삭제하지 않는다.
- 기록 ID가 바뀌면 세트·개별 후보의 임시 선택과 상태 문구를 초기화한다. 이미 적용한 용어는 각 기록의 기존 glossary 저장 경로를 따른다. 녹음 중에는 선택과 추가가 비활성화된다.

## 검증

`node app/frontend/tests/glossary-packs.cjs`: 실제 React 컴포넌트와 순수 추가 함수의 오프라인 행동 검사. 수동 입력 보존, 중복·공백·빈 항목 처리, 정확히 500자 경계, 초과 기존 입력, 기본 비선택, 복수 세트 적용, 기록 전환 초기화, 생략 보고, 녹음 중 비활성을 검사한다. RED 단계에서 기존 구현의 공백 후보 중복 추가와 세트 선택 미지원 실패를 확인한 뒤 구현했다. 결과는 `app/frontend/test-results/glossary-packs.json`.

렌더링·키보드·좁은 화면 검사는 통합 화면 QA에서 별도 확인해야 한다. 이 검사는 실제 Whisper 인식 개선이나 전문 검수의 증거가 아니다. 설치된 실행 파일 변경도 별도 빌드·설치 검증이 필요하다.
