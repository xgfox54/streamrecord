# Stream-Record 잔여 개선 2차 작업 기록

## 소스 반영 사항

이 문서는 소스 변경 기록이다. 테스트 실행·EXE 빌드·설치 완료를 뜻하지 않는다. 최신 실행 상태는 `app/frontend/test-results/finalization.json`의 시각과 종료 코드를 확인한다.

### 1. Whisper 모델 다운로드 검증

- `src-tauri/src/whisper_engine/model_integrity.rs`에 12개 다국어 Whisper 모델의 SHA-256과 Hugging Face 저장소 커밋 `5359861c739e955e79d9a303bcbc70fb988958b1`을 고정했다.
- 출처는 `https://huggingface.co/ggerganov/whisper.cpp`의 각 파일 상세 페이지에 기재된 SHA-256이다. 모델 카드의 SHA-1 및 Xet chunk hash와 혼동하지 않는다.
- 공개 다운로드 명령은 기존 카탈로그 URL을 먼저 검증하고 고정 커밋 URL로 변환한다. Meetily 제작자 서버 또는 임의 저장소를 넣으면 거부한다.
- HTTPS, 443 포트, 인증정보 없는 URL, 명시적으로 열거한 Hugging Face/CDN 호스트로만 리다이렉트한다. 호스트 접미사 와일드카드와 임의 대체 서버는 허용하지 않는다.
- 새 다운로드는 해시 검증 후에만 완료 처리한다. 모델을 실제 메모리에 적재하기 전에도 해시를 검사한다. 이미 적재된 같은 모델의 재사용은 재해시하지 않는다.
- 기존 파일이 있으면 무조건 다시 쓰지 않는다. 검증 실패 시 파일을 보존하고 오류를 반환한다.
- 검증 중에는 최대 1MiB 버퍼를 사용하고 다운로드 파일 크기는 4GiB 이하로 제한한다.
- 기존 다운로드 실패·취소 정리 경로는 유지한다. 임시 파일의 원자적 교체 기능을 새로 구현한 것은 아니다.
- 이 정책은 Whisper 경로에 적용한 것이다. 별도의 Parakeet·내장 요약 모델·Ollama 배포 경로 전체에 같은 검증을 적용했다고 간주하지 않는다.

### 2. 모델 교체 잠금 수정

기존 `load_model`이 현재 모델의 읽기 잠금을 유지한 채 `unload_model`을 호출할 수 있는 경로를 수정했다. 현재 모델명을 복제해 잠금을 해제한 뒤, 새 파일 검증이 성공할 때 기존 모델을 해제한다.

### 3. 실시간 음성 구간 상한

- `src-tauri/src/audio/live_vad.rs`를 추가하고 실시간 파이프라인에 연결했다.
- 기존 VAD의 자연 무음 분절은 유지하면서, 입력 음성을 최대 12초 창으로 제한하고 연속 발언도 창 끝에서 처리한다.
- 창 경계에서 VAD를 재생성해 내부 음성 버퍼도 제한한다. 실제 성능과 경계 인식 정확도는 실측해야 한다.
- 시간은 입력 샘플 수를 누적하여 계산하며 새 창에서 0초로 돌아가지 않는다.
- 반복 종료 요청의 중복 방출을 막는다.
- 이는 **고정 상한 분절**이다. 조용한 지점 탐색, 겹침 전사, 앞뒤 문맥 전달을 구현한 것으로 설명하지 않는다.
- 파일 첨부 전사와 재전사 경로의 기존 정책은 변경하지 않았다.
- 최종 자막 지연에는 Whisper 처리와 대기열 시간이 추가되므로 '12초 이내 자막 출력 보장'이 아니다.

### 4. 녹음 종료 시 남은 버퍼 보존

기존 600ms 믹싱 창보다 짧게 남은 버퍼를 실제 길이로 꺼내 녹음 및 전사 경로에 전달한다. 빈 트랙만 상대 트랙 길이에 맞춰 0으로 채우며, 전체 길이를 600ms로 늘리지 않는다. 여러 종료 신호에도 같은 버퍼를 두 번 보내지 않는다.

## 추가한 검사

Rust 단위검사 11개를 추가했다.

- 모델 목록·고정 URL·리다이렉트 허용/차단·SHA-256 변조·실패 파일 보존: 5개
- 분절 샘플 보존·반복 flush·3시간 샘플 시계·잘못된 입력률: 4개
- 마지막 짧은 버퍼와 전체 샘플 보존: 2개

분절 검사의 일부는 결정론적 가짜 VAD를 사용한다. 3시간 검사는 시간 계산 시뮬레이션이며 실제 3시간 녹음 시험이 아니다. 테스트 코드 작성과 테스트 실행 성공은 구분한다.

## 실행 요청

`tools/finalize-stream-record.ps1`에 다음 단계를 명시했다.

1. 기존 Stream-Record 프런트엔드 회귀검사 실행
2. TypeScript 검사
3. `cargo check --locked --offline`
4. `cargo test --lib stream_record_ --locked --offline -- --nocapture`
5. 사용자 요청에 따른 루트 폴더명 `Stream-Record` 변경(기존 동명 폴더 덮어쓰기 금지)
6. 단계별 종료 코드와 실제 최종 경로 기록

동봉 LLVM 경로의 `libclang16` 오기를 실제 디렉터리인 `libclang-16`으로 고쳤다. 외부 다운로드·앱 설치·Git push는 이 스크립트에 없다. 폴더명 변경은 컴파일 성공과 독립적으로 시도하며 양쪽 결과를 각각 기록한다.

## 아직 별도 구현·검증이 필요한 부분

- STT용 용어 힌트 및 이전 발언 문맥 전달
- 구간별 원음 재생과 회의록 근거 연결
- 저장 음성의 미처리 전사 재개
- VAD 실제 발언·무음·짧은 응답·경계 누락/중복 비교
- 전사 대기열 지연 및 장시간 실제 녹음 시험
- 새 Windows EXE 빌드·기동·설치 검증
- 화자 구분·HLS·HWPX는 후속 확장 기능

기존 녹음, 사용자 설정, 다운로드 모델, 앱 식별자 및 데이터 디렉터리는 변경하지 않는다.
