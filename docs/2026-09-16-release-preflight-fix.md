# Stream-Record v0.1.0 배포 사전 점검 보완

## 확인한 실행 결과

- 승인 요청 `approval_3b783e57-303e-419e-8df2-3d1488c8adf9`의 작업 `ed67557a-6dcd-4017-8fd0-51ec189724bd`는 실제 실행 후 종료 코드 1로 실패했다.
- 로그: `PHASE preflight`, `PASS release-tools-tests`, 이후 `Exactly one installed Stream-Record must be identified`.
- 해당 실행에서는 폴더명 변경, 설치 시도, 소스 푸시, 릴리스 생성 모두 수행하지 않았다. 기존 설치본과 원격 저장소는 이 작업으로 변경되지 않았다.
- 설치 탐색 함수는 DisplayName을 `^stream[- ]record$`와 비교했고, InstallLocation 또는 UninstallString만 사용했다. 현재 실제 설치 등록명과 경로는 아직 별도로 확인하지 못했다. 이 제한이 실제 실패의 유일한 원인이라고 단정하지 않는다.

## 로컬 소스에 반영한 변경

1. 표시명에 버전이 포함된 경우, 앞뒤 공백, StreamRecord 표기를 인식하는 순수 함수를 추가했다. 관련 없는 Meetily 제품은 일치시키지 않는다.
2. 각 레지스트리 항목을 LiteralPath로 읽고 InstallLocation, DisplayIcon, UninstallString, QuietUninstallString에서 실행 파일 경로를 얻는다. 환경변수와 인용부호를 처리한다.
3. 발견한 경로의 파일명, 제품명 메타데이터, 동반 런타임/제거 파일을 확인한다. 개발 프로젝트 내부 실행 파일이나 단독으로 받은 설치 프로그램은 설치 대상으로 취급하지 않는다.
4. 제한된 제품별 사용자 설치 경로를 추가 확인한다. 그래도 후보가 없거나 여럿이면 파일 선택창에서 사용자가 기존 설치 실행 파일을 지정한다. 취소하거나 확인에 실패하면 교체하지 않는다.
5. 설치 위치가 불명확해도 검사·빌드는 수행할 수 있도록 했다. 설치 대상을 확정하고 재검증한 뒤에만 기존 프로그램 종료·백업·교체 단계에 진입한다.
6. 교체 전후 동일한 실행 파일 경로를 확인하고, NSIS /D= 인자로 검증한 기존 설치 폴더를 사용한다. 설치 결과는 새 빌드의 SHA-256과 다시 대조한다.
7. 설치명·경로 파싱, 빌드/설치 단계 분리, 설치 대상 재검증에 대한 회귀검사 3개를 추가했다.

수정 파일:
- `tools/windows-release-host.ps1`
- `tools/release-stream-record.mjs`
- `tools/test-release-tools.mjs`

## 검증 구분

기존 배포 도구 검사 8개는 위 실패한 실행의 사전 점검에서 통과했다. 이번 변경 후에는 command_run이 별도 승인을 요구해 새 검사 11개를 아직 실행하지 못했다. 다음 승인된 전체 배포 실행의 첫 단계에서 PowerShell 구문과 추가 순수 함수 검사를 포함해 다시 검사한다. 통과 전에는 이번 수정본이 검증됐다고 주장하지 않는다.

이전 프런트엔드 40개·TypeScript·Rust 컴파일 통과 기록은 별도 실행 기록이다. 실제 음성 캡처·Whisper 인식 정확도·장시간 녹음 검증으로 해석하지 않는다.

## 배포 조건

수정된 정확한 명령은 별도 로컬 승인이 필요하다. 입력 토큰은 마스킹된 로컬 입력창에서 받고 메모리와 비공개 자식 프로세스 파이프에서만 사용한다. 설치·푸시·릴리스 완료 여부는 실행 결과와 실제 원격 파일 검증으로 판단한다. 새 승인 요청 전 코드와 검사 내용을 고정한다.

참고: NSIS 공식 Command Line Usage의 /D= 규칙(마지막 인자, 경로 인용부호 금지): https://nsis.sourceforge.io/Docs/Chapter3.html
